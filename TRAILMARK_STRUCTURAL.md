## Available-passes gap

The `trailmark-structural` skill brief asks for:

```bash
trailmark analyze --passes blast_radius,taint,privilege_boundary,complexity \
                  --language typescript <target>
```

`trailmark 0.3.0`'s `analyze` subcommand **does not implement `--passes`**. Its only structural flags are `--summary` and `--complexity <N>`, and structural data is split out across two sibling subcommands:

```text
$ trailmark analyze --help
usage: trailmark analyze [-h] [--language LANGUAGE] [--summary]
                         [--complexity COMPLEXITY]
                         path
$ trailmark --help
positional: {version,analyze,diff,entrypoints,augment}
```

There is no `taint` or `privilege_boundary` pass exposed by the CLI in this version. Per skill rule "do not silently install unless allowed", I did one allowed `uv tool install trailmark` before discovering the version mismatch. **Deeper structural passes are skipped with reason; the data the version *can* produce is included below as a faithful substitute (entrypoints + complexity + class containment + call graph fragments).**

## Substitute for `blast_radius` pass

`trailmark 0.3.0` does not emit a numeric blast radius. The closest reproducible signal is **call-graph fan-in** to entrypoints. Using the call-graph diagram in `DIAGRAMMING_CODE.md`:

| Function | Reachable from entrypoint(s) | Notes |
|----------|------------------------------|-------|
| `PerPaymentClient.request` | `cli:main` (CLI) and indirectly `app.api.per-proxy.health.route:GET` | Single network chokepoint for **all** PER calls — its blast radius is the entire `per-client` public API (13 methods). |
| `createPerTools` | `cli:main` via `PrivateMppAgent` constructor | Defines the agent's tool surface; any future tool added here can be invoked end-to-end through the CLI. |
| `chatCompletion` | `cli:main` | Reaches `chatCompletionFetchFallback` and the OpenRouter SDK; isolated from PER. |
| `payResource` | `cli:main` | Reaches arbitrary `fetch`; this is the largest "outbound" blast radius and the OWASP-LLM concern called out in the PRD. |

## Substitute for `taint` pass

`trailmark 0.3.0` has no taint pass. A manual trace using the call graph (and confirmed by reading the source under `packages/`):

- **Source → sink** (taint candidates):
  - `process.env.OPENROUTER_API_KEY` → `chatCompletion()` → OpenRouter SDK / `fetch`. Sensitive sink for credential leak; mitigated by HTTPS-only.
  - `process.env.MPP_SECRET_KEY` / `MPP_TEMPO_*` → `apps/web/app/api/example-paid/route.ts:GET` → `mppx` `createGate` → 402 challenge. Verifier-side handling of HMAC-style secret.
  - Tool-arg `url` (LLM-controlled) → `payResource()` → `fetch`. **Untyped/unvalidated URL** taint flow — explicitly flagged in `docs/architecture-low-level.md` and `docs/PRD.md` as needing host allowlists. This is the headline taint issue and survives Zod because Zod validates `string.url()` shape but not host policy.
  - HTTP response body (`res.text()` / `res.json()`) → `parseJsonSafe()` → `enrichParsed()` → caller. Treated as untrusted; `tryParse*` helpers preserve unknown fields, which is the right behavior.

## Substitute for `privilege_boundary` pass

The four privilege boundaries trailmark would otherwise enumerate are visible in the entrypoint output above:

1. **Internet → Next.js handlers** (`apps/web/app/api/*`). Untrusted external; high-asset.
2. **CLI operator → `agent.src.cli:main`**. Trusted internal; low-asset.
3. **Agent → OpenRouter** (LLM provider). Outbound credential boundary via `OPENROUTER_API_KEY`.
4. **Agent → `payResource → fetch(arbitrary URL)`**. The agent's *open-egress* boundary; should be gated by allowlists before any production use.
